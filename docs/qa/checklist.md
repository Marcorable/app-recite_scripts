# 양 플랫폼 QA 전략 및 출시 체크리스트

> Issue #33 산출물. `AGENTS.md`, `docs/requirements.md`, `docs/PRD.md`의 출시 기준을 실행 가능한 검증으로 연결한다.

## 1. 판정 원칙

- 결과는 `미실행 / 통과 / 실패 / 차단 / 해당 없음` 중 하나로 기록한다.
- P0와 P1 실패는 모두 출시를 차단한다. 해당 항목을 통과하기 전에는 예외로 출시하지 않는다.
- `[공통]`은 iOS와 Android에서 각각 확인한다. `[실기기]`는 Simulator나 Emulator로 대체하지 않는다.
- STT 테스트의 대본은 직접 작성한 중립 문장만 사용한다. 사용자 대본·전사문·음성을 저장소, 로그, 분석 도구에 남기지 않는다.
- 자동 테스트는 결정적인 fake adapter를 사용한다. 음성 정확도, 온디바이스 모델, 마이크 생명주기는 실기기에서 별도로 검증한다.

## 2. 검증 계층과 책임

| 계층 | 범위 | 실행 위치 | 책임 |
|---|---|---|---|
| 순수 Dart unit | 정규화, 순방향 매칭, 회차, generation, 취소 | 로컬·CI | QA 자동화 |
| Flutter widget | 추가·삭제·설정·낭독·완료, 오류, semantics, 큰 글씨 | 로컬·CI | QA 자동화 |
| 네이티브 unit | iOS·Android STT 이벤트, 오류 매핑, 자원 해제 | 로컬·CI | QA 자동화 |
| Simulator/Emulator | 저장, 화면 전환, 미지원·권한 UI, 레이아웃 | 로컬 QA | QA |
| 실기기 | 실제 마이크, 온디바이스 한국어 STT, 백그라운드, 장시간 | 내부 배포 | QA + 기기 보유자 |
| 개인정보 검사 | 네트워크, 샌드박스, 로그, 백업 제외 | 실기기·빌드 산출물 | #105 |

자동화 책임은 #34, #35, #105, #106, #107에 나누고 실기기 출시 판정은 #36에서 관리한다.
